# WOW 团队活动排班工具设计说明

## 1. 项目背景

本项目用于为《魔兽世界》WotLK 版本工会活动组织者提供一个桌面排班工具，运行于 Windows 10 环境，以单体 EXE 形式分发，可附带本地数据文件。工具核心目标是帮助组织者维护自然人、角色、活动班次、报名记录、预分配名单以及最终 RAID 排班结果，并通过自动排班与增益/减益覆盖检查功能降低人工协调成本。

结合当前业务场景：

- 参与活动的自然人约 25-30 人。
- 大多数自然人拥有 2-3 个角色，部分拥有 4-5 个或更多角色。
- 固定活动日为每周五、周六、周日、周一。
- 部分自然人无法参加特定时段活动。
- 每次活动阵容为 25 个角色。
- 常规阵容要求大致为 2-3 Tank、4-5 Healer、其余为 DPS。
- 阵容应尽可能满足职业增益与敌对减益覆盖。

因此，本项目不仅是一个静态排班表编辑器，还需要具备：

1. 多自然人、多角色、多职责建模能力。
2. 活动/班次配置能力。
3. 自动排班与人工修正结合能力。
4. RAID Buff/Debuff 覆盖检查能力。
5. 模板化编排能力。
6. 通过字符串进行导入/导出与报名流转的离线协作能力。

---

## 2. 建设目标

### 2.1 目标

构建一个可离线运行的 Windows 桌面应用，支持以下核心能力：

- 管理自然人、角色、职业、职责、可出勤时间。
- 管理活动与班次。
- 设计阵容模板。
- 自动生成候选排班结果。
- 查看当前排班的 Buff/Debuff 覆盖情况。
- 导入玩家报名信息并转化为预分配名单。
- 手工调整排班并导出结果。
- 将所有数据保存在本地 data 文件中。

### 2.2 非目标

首版暂不包含：

- 云同步。
- 多组织者实时协作编辑。
- 战网 API 实时接入。
- 复杂权限系统。
- 手机端适配。

## 3. 平台与技术选型

## 3.1 运行平台

- 操作系统：Windows 10。
- 部署形式：单体 EXE 可执行文件。
- 数据存储：应用目录下的 data 文件夹。

## 3.2 技术方案

建议首版采用：

- **Python 3.12+**
- **PySide6**：桌面 GUI。
- **SQLite**：本地结构化数据存储。
- **JSON**：导入/导出交换格式。
- **PyInstaller**：打包单体 EXE。

### 3.3 选择理由

- PySide6 适合快速构建 Windows 桌面软件。
- Python 便于快速实现排班逻辑、规则引擎与导入导出。
- SQLite 适合单机持久化与后续复杂查询。
- PyInstaller 可满足单体 EXE 打包需求。

## 4. 业务对象建模

## 4.1 自然人（Person）

表示真实参与活动的玩家。

关键属性：

- 唯一 ID
- 昵称/标识名
- 备注
- 默认可参加活动日
- 特定日期不可参加记录

## 4.2 角色（Character）

表示自然人在游戏中的具体角色。

关键属性：

- 唯一 ID
- 所属自然人 ID
- 角色名
- 职业（基于 WotLK）
- 可承担职责集合（Tank / Healer / DPS，可多选）
- 主修/副修标记
- 装等/优先级备注（预留）
- 是否启用

## 4.3 职业（Class）

WotLK 版本先采用 10 职业建模：

- 战士 Warrior
- 圣骑士 Paladin
- 猎人 Hunter
- 潜行者 Rogue
- 牧师 Priest
- 死亡骑士 Death Knight
- 萨满 Shaman
- 法师 Mage
- 术士 Warlock
- 德鲁伊 Druid

> 说明：WotLK 实际还包含武僧之前的经典体系，此处按需求明确采用 10 职业建模，不额外扩展。

## 4.4 职责（Role）

- Tank
- Healer
- DPS

## 4.5 活动（Event）

表示一组可报名班次的活动，如某周团队活动。

关键属性：

- 唯一 ID
- 活动标题
- 活动说明
- 周期或所属周次
- 创建时间
- 是否归档

## 4.6 活动班次（EventShift）

表示某活动下的具体场次，如周五、周六晚活动。

关键属性：

- 唯一 ID
- 所属活动 ID
- 日期
- 星期标记
- 开始/结束时间
- 目标模板 ID
- 状态（未开始 / 报名中 / 已排班 / 已结束）

## 4.7 阵容模板（Template）

描述某类活动期望的职责人数与约束。

关键属性：

- 唯一 ID
- 模板名称
- Tank 目标人数
- Healer 目标人数
- DPS 目标人数
- 是否允许 Tank / Healer 范围浮动
- 备注

## 4.8 报名记录（Signup）

表示玩家对某一班次提交的报名。

关键属性：

- 唯一 ID
- 班次 ID
- 自然人 ID
- 角色 ID
- 报名职责
- 报名优先级/意愿顺位
- 时间戳
- 导入批次 ID

## 4.9 预分配记录（PreAssignment）

表示组织者已接收但尚未最终定稿的候选安排。

## 4.10 最终排班记录（Assignment）

表示某班次最终确认的 25 人阵容与职责。

关键属性：

- 班次 ID
- 角色 ID
- 自然人 ID
- 最终职责
- 是否锁定
- 排班来源（自动 / 手动）
- 序号/分组位置

## 5. 功能设计

## 5.1 自然人/角色管理

支持：

- 新增、编辑、删除自然人。
- 为自然人新增多个角色。
- 设置角色职业与可承担职责。
- 设置自然人的固定不可参与日期/星期。
- 支持启用/停用角色。

界面建议：

- 左侧自然人列表。
- 右侧显示其角色列表与详情编辑区。
- 支持搜索与筛选。

## 5.2 活动与班次管理

支持：

- 新建活动。
- 批量生成周五/六/日/一活动班次。
- 编辑单个班次时间。
- 为班次指定模板。
- 标记报名状态与排班状态。

## 5.3 阵容模板管理

支持：

- 新建模板。
- 设置 Tank/Healer/DPS 人数。
- 配置阵容目标，例如 2T/5H/18DPS。
- 为不同难度或 Boss 场景保存不同模板。

## 5.4 排班工作台

这是核心功能区域。

应支持：

- 选择某活动班次。
- 查看当前报名池、预分配名单、最终阵容。
- 一键自动排班。
- 手动拖拽/替换/锁定角色。
- 检查阵容人数是否满足模板。
- 检查自然人是否重复上场。
- 检查角色职责与可承担职责是否一致。
- 查看当前阵容 Buff/Debuff 覆盖情况。

## 5.5 Buff/Debuff 覆盖检查

工具需内置 WotLK 常见团队增益与敌对减益映射。

检查输出示例：

- 已覆盖：王者祝福、耐力、嗜血/英勇、法强、破甲、法术易伤等。
- 缺失：战复、命中光环、近战急速、法术暴击增益等。
- 重复过多：某些 Buff 有多个来源，可提示冗余但不报错。

此功能应当：

- 基于当前 25 人阵容实时刷新。
- 显示 Buff/Debuff 名称、覆盖状态、来源角色/职业。
- 支持按“增益”“减益”分类展示。

## 5.6 导入/导出

应支持三类数据的导入导出：

1. 自然人与角色名单。
2. 活动班次表。
3. 排班表。

形式：

- 文件导入导出（JSON / CSV）。
- 字符串导入导出（Base64 + JSON 压缩结构）。

## 5.7 报名流程支持

### 组织者端流程

1. 创建活动与班次。
2. 导出活动班次表字符串。
3. 将字符串发送给玩家。
4. 收集玩家回传的报名字符串。
5. 导入报名字符串。
6. 报名信息进入预分配名单。
7. 自动排班与人工协调。

### 玩家端流程

1. 导入活动班次表字符串。
2. 选择感兴趣班次。
3. 为自己的角色选择报名职责。
4. 导出报名字符串。
5. 发送给组织者。

### 冲突处理

当同一自然人在同一班次报名多个角色时：

- 默认只允许最终上场一个角色。
- 可保留多个候选报名，但自动排班阶段只能选择其中之一。

## 6. 自动排班设计

## 6.1 目标

在满足模板人数要求和出勤约束前提下，尽可能生成一个平衡阵容，并提高 Buff/Debuff 覆盖完整度。

## 6.2 基础约束

- 总人数 = 25。
- Tank 人数满足模板要求。
- Healer 人数满足模板要求。
- DPS 人数满足模板要求。
- 同一自然人在同一班次最多选择一个角色。
- 角色必须已报名或允许加入候补池。
- 角色承担职责必须属于该角色可承担职责。
- 不可安排到自然人不可参与的时间。

## 6.3 优化目标

自动排班可按如下优先级进行评分：

1. 满足硬性职责人数。
2. 满足自然人时间约束。
3. 提高关键 Buff 覆盖数量。
4. 提高关键 Debuff 覆盖数量。
5. 控制重复来源冗余。
6. 尽量提高自然人轮换公平性。
7. 优先使用被组织者锁定的预分配角色。

## 6.4 初版算法建议

首版建议采用“规则过滤 + 贪心评分 + 人工修正”的方式：

1. 根据班次和模板筛出合法报名角色。
2. 先选 Tank，再选 Healer，再补 DPS。
3. 每一步按综合评分选取最佳候选：
   - 是否提供当前缺失 Buff/Debuff
   - 是否为唯一来源
   - 是否符合报名职责
   - 是否被组织者优先标记
   - 是否造成自然人冲突
4. 生成候选阵容后再进行局部交换优化。

后续版本可升级为：

- 整数规划
- 回溯搜索
- 启发式搜索
- 多目标优化

## 9. 导入导出协议设计

## 9.1 文件协议

首版使用 JSON：

- 名单文件 `.wrst_roster.json`
- 班次文件 `.wrst_event.json`
- 排班文件 `.wrst_schedule.json`
- 报名文件 `.wrst_signup.json`

## 9.2 字符串协议

建议结构：

- JSON 对象
- UTF-8 编码
- zlib 压缩
- Base64 编码

外层字段建议：

- `protocol_version`
- `payload_type`
- `created_at`
- `source`
- `payload`
- `checksum`

## 14. 结论

本工具定位为一个面向工会活动组织者的离线桌面排班系统。其核心价值在于：

- 降低多角色、多班次、多职责场景下的人工整理成本。
- 通过自动排班加快出表效率。
- 通过 Buff/Debuff 检查提升阵容完整性。
- 通过字符串交换报名，适应工会成员之间的轻量协作方式。

首版应优先落地“可用”而非“最优”，即先完成完整业务闭环，再迭代提升排班算法与规则精度。
